# Hash Management

## Smart Contract-based Hash Management
This document provides an overview of the **Web3DBHashManagement** smart contract, which is designed to manage hash records, facilitate secure data sharing, and maintain access control within the Web3DB system.

<Admonition type="info" title="Purpose">
  The Web3DB smart contract enables decentralized hash management, CID sharing, and revocation, ensuring secure and tamper-proof data operations using blockchain technology.
</Admonition>

## Contract Overview

The **Web3DBHashManagement** smart contract provides key functionalities such as:

- **Storing hash records** for various database operations (create, insert, update, delete, share).
- **Sharing CIDs (Content Identifiers)** with other users.
- **Revoking access** to previously shared CIDs.
- **Retrieving hash history** and latest state information.
- **Role-based CID management** to ensure only authorized users can share or revoke access.

## Key Data Structures

### 1. **Hash Records**

Hash records are used to track operations on database partitions. Each hash record contains the following details:

| Field        | Type     | Description                                    |
|--------------|----------|------------------------------------------------|
| `hash`       | `string` | IPFS hash representing the current state       |
| `prevHash`   | `string` | Previous state hash                            |
| `recordType` | `string` | Type of operation (`create`, `insert`, etc.)   |
| `timestamp`  | `uint256`| Timestamp of the operation                     |
| `flag`       | `string` | Indicates the state (`initial`, `latest`)      |
| `rowCount`   | `uint256`| Number of rows affected                        |

### 2. **CID Sharing**

Users can share CIDs (Content Identifiers) with others. Each shared CID is recorded with the following fields:

| Field     | Type     | Description                             |
|-----------|----------|-----------------------------------------|
| `cid`     | `string` | The shared IPFS content identifier      |
| `owner`   | `address`| Address of the user sharing the CID     |
| `isValid` | `bool`   | Indicates whether the CID is still valid|

### 3. **User Tables**

The contract maintains a list of tables owned by each user. This helps in ensuring that only the owner can share or manage data associated with their tables.

## Main Functions

### `addHashMapping`

```solidity
function addHashMapping(
    string memory tableName,
    string memory partition,
    string memory hash,
    string memory prevHash,
    string memory recordType,
    string memory flag,
    uint256 rowCount
) public returns (bool)
```

Adds a new hash record for a specific table and partition. Emits the `HashMappingAdded` event upon successful addition.

- **Parameters**:
  - `tableName`: The name of the table.
  - `partition`: The partition of the table.
  - `hash`: The current state hash.
  - `prevHash`: The previous state hash.
  - `recordType`: Type of operation (`create`, `update`, etc.).
  - `flag`: Indicates the state (`initial`, `latest`, `stable`).
  - `rowCount`: Number of rows affected by the operation.

- **Returns**: `true` if the operation is successful.

### `shareCID`

```solidity
function shareCID(
    address user,
    string memory tableName,
    string memory cid
) public returns (bool)
```

Allows a user to share a CID with another user. Only the owner of the CID can share it. Emits the `CIDShared` event upon successful sharing.

- **Parameters**:
  - `user`: The address of the user to share the CID with.
  - `tableName`: The name of the table associated with the CID.
  - `cid`: The IPFS content identifier to be shared.

- **Returns**: `true` if the operation is successful.

### `getSharedCIDs`

```solidity
function getSharedCIDs(
    address user,
    string memory tableName
) public view returns (string[] memory cids, address[] memory owners)
```

Retrieves the list of shared CIDs for a specific user and table.

- **Parameters**:
  - `user`: The address of the user for whom to retrieve shared CIDs.
  - `tableName`: The name of the table.

- **Returns**:
  - `cids`: Array of shared CIDs.
  - `owners`: Array of corresponding CID owners.

### `revokeCIDAccess`

```solidity
function revokeCIDAccess(
    address user,
    string memory tableName,
    string memory cid
) public returns (bool)
```

Revokes access to a shared CID. Only the owner of the CID can revoke it.

- **Parameters**:
  - `user`: The address of the user whose access is being revoked.
  - `tableName`: The name of the table associated with the CID.
  - `cid`: The IPFS content identifier to revoke.

- **Returns**: `true` if the operation is successful.

### `getLatestHash`

```solidity
function getLatestHash(
    address user,
    string memory tableName,
    string memory partition
) public view returns (string memory)
```

Retrieves the latest hash for a specific user, table, and partition.

- **Parameters**:
  - `user`: The address of the user.
  - `tableName`: The name of the table.
  - `partition`: The partition of the table.

- **Returns**: The latest hash as a `string`.

### `getHashHistory`

```solidity
function getHashHistory(
    address user,
    string memory tableName,
    string memory partition
) public view returns (
    string[] memory hashes,
    string[] memory prevHashes,
    string[] memory types,
    uint256[] memory timestamps,
    string[] memory flags,
    uint256[] memory rowCounts
)
```

Retrieves the history of hash records for a specific user, table, and partition.

- **Parameters**:
  - `user`: The address of the user.
  - `tableName`: The name of the table.
  - `partition`: The partition of the table.

- **Returns**:
  - Arrays of hashes, previous hashes, record types, timestamps, flags, and row counts.

### `getUserTables`

```solidity
function getUserTables(address user) public view returns (string[] memory)
```

Retrieves the list of tables owned by a specific user.

- **Parameters**:
  - `user`: The address of the user.

- **Returns**: An array of table names.

## Security Considerations

- **Ownership Verification**: The contract ensures that only the owner of a CID can share or revoke access.
- **Data Integrity**: By storing hashes, the contract guarantees that data changes are tracked and verifiable.
- **Access Control**: The use of CID sharing and revocation enables fine-grained access control.

## Conclusion

The **Web3DBHashManagement** smart contract is a core component of the Web3DB system, enabling decentralized and secure data management. By integrating IPFS and leveraging blockchain technology, it ensures data integrity, transparency, and controlled sharing.
